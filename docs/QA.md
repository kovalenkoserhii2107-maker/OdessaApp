# Проверка улучшений — 27 сентября 2026

## Объём

Существующий проект Antigravity, локальный браузер Codex. Сохранены сюжетные тексты, Firebase-проект и SVG районов. Изменены надёжность движка, рабочий экран и PWA. Это проверка конкретных сценариев, не заявление о полной WCAG-совместимости.

## Исходные наблюдения

1. Экран входа снимался в браузере: только Google, без возможности ознакомиться с кампанией. Дальнейший исходный экран был недоступен без входа; замечания о старом досье и сохранениях основаны на коде, а не на выдуманном прохождении.
2. По коду досье просило выбрать сотрудника внизу, но overlay закрывал штат. Стоимость и обязательный навык не проверялись в движке.
3. Вложенные массивы и метрики изменялись на месте, reset возвращал мутированный singleton. Последствия не удалялись. `JSON.parse` мог уронить весь экран.
4. В manifest были корневые пути при base `/odessa-app/`, PNG-иконки отсутствовали, предложение установки было только для iOS.

## Автоматическая проверка

`npm run check`: Vitest + TypeScript + production/PWA build.

Проверки: чистота перехода при повторном вызове React updater; повторное решение; другая роль; чужой сотрудник; неправильный навык; закрытая глава; несуществующий выбор; занятость/усталость; нехватка ресурса; независимый reset; границы метрик; последствия ровно один раз; догонялка после отсутствия; ручная смена; зависимости глав; согласованность контента; round-trip сохранения; повреждённый JSON/схема; quota при backup; просроченные последствия старой версии.

## Ограничения

- Google OAuth не завершался от имени пользователя; интеграция сохранена, ошибки переведены на понятный язык. Нужны разрешённые домены в Firebase.
- Настоящий iPhone и диалог установки ОС не эмулировались. Manifest, PNG и service worker проверяются в production build.
- Совместной серверной игры ещё нет; это явно указано в приложении и README.
- Рассказ и баланс не менялись. Темп 12 часов сохранён из версии Antigravity.

## Повторная проверка после жалобы на телефон

Предыдущая адаптация не была достаточной: панель вкладок уходила при прокрутке, команда находилась под списком, досье объединяло слишком много действий. Интерфейс переработан под отдельные экраны и два шага назначения.

- 390×844: входящие, карта, журнал и команда доступны через закреплённую нижнюю панель. Пройдено дело Ткача «Один объект, два номера» → история изменений → Алиса Вольская. Ресурс 100 → 82, факты 0 → 12, стабильность 50 → 48, один ответ в журнале; Алиса занята, свободны 2/3. После reload и обновления service worker значения сохранены.
- 320×568: документ ровно 320×568, без внешнего/горизонтального overflow; нижние кнопки высотой 57 px. Досье с карты открывается, нижний вариант решения выбирается через внутреннюю прокрутку, переход к сотруднику работает; отправка остаётся внизу экрана.
- 844×390: используется мобильная раскладка, а не сжатый desktop; полноэкранное досье сохраняет прокручиваемый текст и нижнюю кнопку.
- Автоматические проверки: 22 теста логики, TypeScript, production build. Дополнительно собраны и проверены PWA для `/`, `/OdessaApp/`, `/odessa-app/`: start URL, scope, id, PNG, ссылка на manifest, offline fallback. Эти проверки запускаются после каждой сборки.
- Скриншоты `.local/qa/06-mobile-before.png`, `07-mobile-inbox.png`, `08-mobile-assignment.png` — локальные артефакты проверки.

Публикация пока не подтверждена: 27 сентября оба предполагаемых GitHub Pages URL отвечают 404; API Pages для обоих репозиториев также возвращает 404. Старая ветка gh-pages содержит manifest со start_url `/`, хотя сборка лежит в `/odessa-app/`. Это найденная причина неправильного адреса ярлыка, но без ссылки пользователя нельзя подтвердить, что телефон открывает именно этот хостинг. Актуальная ссылка запрошена. На настоящем iPhone установка и safe-area не проверялись; проверка размеров в браузере не подменяет такую проверку.
