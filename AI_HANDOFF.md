## Что фактически работает

18 дел из существующего `content.ts`, включая добавленные Antigravity сюжетные этапы 2 и 3. Их тексты сохранены. Смена — 12 часов от старта/последнего ручного завершения. «Утро/вечер» — игровые обозначения, не привязка к 09:00 и 21:00 по часам. Исходный пользователь обсуждал часовой tick; окончательное решение по серверному темпу не принято.

Эффекты выбора немедленные; каждый сотрудник занимает одну смену; +25 усталости при назначении и −25 при смене. Ресурс ограничен стартовыми 100, цена списывается один раз. Бесконечного восстановления денег не добавлено. Все текущие ветки рассчитаны на этот ресурс. Двойной submit отвергается. `minTick` и `requires` проверяются внутри движка, а не только в UI. Последствия удаляются после применения; офлайн-догонялка учитывает весь прошедший период за один переход.

Досье — native dialog с возвратом фокуса, Escape и отдельной прокручиваемой частью. Сотрудники назначаются в самом досье. На телефоне — фиксированный экран 100dvh с четырьмя нижними вкладками входящих/карты/журнала/команды, внутренней прокруткой и safe-area. Досье вынесено в components/Dossier.tsx: два шага (решение → сотрудник), полноэкранный диалог на телефоне, закреплённые кнопки. Адаптация в src/mobile.css, включая телефоны в альбомной ориентации. SVG районов сохранён; координаты событий схематические, маркеры больше не вычисляются по индексу списка. Шрифты локальные. PWA использует относительные start_url/scope/иконки, стабильный id из base. postbuild validates the manifest, icons and offline fallback, and creates 404.html/.nojekyll. The current gh-pages build is live at /OdessaApp/.

## Сохранения и совместимость

`odessa_save` — существующая локальная кампания, общая для браузера, не отдельная для Google uid. `odessa_demo_save` — отдельная демо-кампания. Демо доступно без входа и не означает обход серверной авторизации: серверной игры пока нет.

Schema Zod проверяет данные; повреждённый raw сохраняется в `<key>:backup:<timestamp>`, затем создаётся новая кампания. Если резервную копию создать нельзя, автоматическая запись запрещается, UI работает в памяти и сообщает об этом. Старые дубликаты решений убираются, метрики ограничиваются, уже просроченные последствия старого движка не повторяются. Нельзя достоверно восстановить уже удвоенные исторические метрики; не пытаться молча переиграть все старые выборы.

Не мутировать вложенные массивы в React updater. Использовать чистые функции `createGame`, `decide`, `advanceShifts`, `catchUp`, `finishShift`. Не возвращать прежний singleton INITIAL_STATE при reset.
